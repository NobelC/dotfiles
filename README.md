# dotfiles

Arch + Hyprland environment managed with GNU stow and themed end to end
by Aether. Every top-level directory is a stow package whose internal
tree mirrors `$HOME`:

```
waybar/.config/waybar/...   ->  ~/.config/waybar/...
scripts/.local/bin/...      ->  ~/.local/bin/...
```

Deploy a single package: `stow -R <package>`. Full bootstrap: `./install.sh`.

## Components

| Directory | Role |
|---|---|
| `hypr/` | Hyprland configuration in Lua (`hl` API): modular `conf/`, submaps, scratchpads, window rules, wallpapers |
| `waybar/` | Bar; pill-shaped workspaces in CSS; colors via symlink to Aether |
| `eww/` | Widgets (sys-stats panel) and click-catcher; static GTK CSS |
| `wofi/` | Launcher; colors via symlink to Aether |
| `mako/` | ASCII-flow notifications; colors via native `include` |
| `ghostty/` | Terminal; theme via `config-file` include with `?` fallback |
| `nvim/` | LazyVim; colorscheme via `dofile` of the Aether-generated spec, tokyonight fallback |
| `btop/` | Monitoring; `color_theme = "aether.theme"` |
| `yazi/` | File manager |
| `fastfetch/` | Fetch with a corpus of monochrome ASCII logos (`logo-fast/`) |
| `aether/` | Per-application custom hooks for the theme engine |
| `scripts/` | Own utilities and daemons (theme bus, screenshots, mic, sysstat) |
| `systemd/` | User services |
| `pacman/` | Hook that regenerates manifests and registers services on every transaction |

## Theme pipeline (the contract)

Single source of truth: `~/.config/aether/theme/`, generated by Aether
from the active wallpaper.

**Absolute rule: no hex literals live outside that directory.**
Audit with:

```bash
grep -RInE '#[0-9a-fA-F]{6}' ~/.config --exclude-dir=aether
```

Integration patterns, in order of preference when adding a new consumer:

| Consumer | Pattern | Reload on theme change |
|---|---|---|
| Mako | Native consumer `include` | `makoctl reload` (hook) |
| Waybar, Wofi, EWW, Hyprland | Symlink to the Aether artifact | restart/reload (hook) or per-launch |
| Ghostty, Neovim | include/dofile of the generated artifact | relaunch |
| Btop | Copy into `themes/` via hook | relaunch |

Principles:

- **Single ownership**: themed artifacts are neither versioned by stow
  nor copied ad hoc. They are owned by the hook (symlink/copy) or by the
  native include. A file with two owners drifts in silence.
- **Push notification with a fallback bus**: whoever changes the palette
  notifies. Since `aether --generate` does not dispatch hooks,
  `scripts/.local/bin/theme-watch-daemon.sh` watches
  `theme/waybar-style.css.tpl` via inotify and dispatches every
  `custom/*/post-apply.sh` on any rewrite, regardless of the changer.
- **Relaunch contract**: btop, Ghostty and Neovim pick up the theme at
  startup. No hook ever kills user-interactive processes; live
  recoloring is the responsibility of daemons exposing a reload verb
  (eww, mako, waybar).

## Packages and services

`pkglist-official.txt` and `pkglist-aur.txt` are manifests regenerated
by `pacman/hooks/dotfiles.hook` on every transaction: they change as a
block, so commit them as a block. `services-scope.txt` and
`services-user.txt` are the whitelist of services the hook enables
automatically.

## Bootstrap on a new machine

1. `git clone` + `./install.sh`
2. Run Aether once before opening themed apps. Configs with graceful
   fallbacks (`?` in Ghostty, conditional `dofile` in nvim) survive
   without a theme; the rest wait for their symlink.

## Conventions

- Commits: Conventional Commits in English; the body explains the why.
- Generated files never enter git: the symlinks referencing them do,
  their content does not.
- Editing under `~/.config` **is** editing the repo (stow symlinks file
  by file). The only exception is derived artifacts, which do not live
  in git.

## Known debt

- `yazi/` and `fastfetch/` UI colors do not consume Aether yet: the
  engine emits no artifacts for them, and wiring them would require a
  custom generator from `theme/colors.toml`. A taken decision, not an
  oversight.
